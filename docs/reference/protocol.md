# 通信协议

## 端口

| 端口 | 协议 | 用途 |
|---|---|---|
| 45900 | TCP | 教室端监听：握手、控制消息、音频与图片分片都走这一条连接 |
| 45901 | UDP | 教室端监听广播，教师端靠它自动发现 |
| 45902 | TCP（回环） | 教室端投递到本机 ClassIsland 插件的入口，只绑 `127.0.0.1` |

控制消息与音频/图片**共用一条 TCP 连接**，靠帧头里的类型字节区分 —— 避免额外端口与乱序问题。

## 分帧

```
[4 字节大端长度][1 字节类型][负载]
```

长度字段包含类型字节。单帧负载上限 1 MiB（防御异常长度导致的巨量分配）。

类型：`1 = 控制（JSON）`、`2 = 音频分片（裸 PCM）`、`3 = 图片分片`。

## 控制消息

JSON，用 `type` 字段区分。主要几种：

| type | 方向 | 说明 |
|---|---|---|
| `hello` | 教师端 → 教室端 | 握手，带客户端名与协议版本 |
| `textShout` | 教师端 → 教室端 | 文字喊话，含语速、音量、是否打断，以及展示参数 |
| `audioStart` / `audioEnd` | 教师端 → 教室端 | 语音流的两端，中间夹着音频分片 |
| `imageStart` / `imageEnd` | 教师端 → 教室端 | 图片的三段式的两端，中间夹着图片分片 |
| `stop` | 教师端 → 教室端 | 立即停止 |
| `status` | 教室端 → 教师端 | 运行状态（待机/朗读/播放/静音/音量）与**能力声明** |
| `ack` / `error` / `bye` | 双向 | 回执、错误、断开 |

### 协议版本与能力

握手时带协议版本，不匹配会被明确拒绝并提示升级 ——
版本号存在的意义就是"线路格式可能变了"。

此外教室端在 `status` 里报自己会哪些能力（图片、展示参数）。
教师端据此把用不了的选项禁掉：让人选好了却发不到对面，比一开始就禁掉糟得多。
旧版教室端不发这个字段，教师端按"只有基础能力"处理。

## 音频

16 kHz 单声道 16 bit PCM，每 20 毫秒一片（640 字节）。

中继那条路上，客户端会先攒到 100 毫秒再发一次 HTTP 请求 ——
直接发就是每秒 50 个请求，服务器受不了。分片在服务器上以 base64 放进信封转发。

## 图片

和音频一样三段式：声明（带总字节数、说明文字、展示参数）→ 若干分片 → 收尾。

- 局域网每片 48 KiB，中继每片 10 KiB；
- 中继分片小的原因：服务器对单个请求体有 16 KiB 上限，而 base64 还要再放大三分之一；
- 单张图片上限 8 MiB —— 教室端会照着声明里的字节数预分配缓冲，
  不设上限就等于让对方决定我们分配多少内存。

教室里那台电脑边收边拼，收齐才显示。

## 中继链路

教师端与教室端都不主动连对方，而是各自与服务器通信：

- 教师端发喊话：普通 HTTP POST；
- 两端收消息：**长轮询**（一轮最多等 25 秒）；
- 服务器只做转发，不理解内容。

### 事件信封

一条扁平结构（`kind` + 各字段），不为每类事件建一个类型：
这条线路上跑的是高频音频分片，多一层多态解析就多一份开销，
而且服务端只是转发，"服务器不需要懂业务"这一点更清楚。

### 鉴权

| 谁 | 令牌 | 怎么带 |
|---|---|---|
| 教室端 | 注册后服务器签发 | 请求头 `X-Relay-Token` |
| 教师端 | 绑定教室后签发（绑定在内存里，服务器重启后要重新绑定） | 路径参数 |
| 账号登录 | 登录/注册后签发 | 请求头 `X-Auth-Token` |

令牌走请求头而不是查询串：查询串会进访问日志，口令这类东西不该留在日志里。
