# 验证

这个项目没有单元测试框架，取而代之的是三样东西：**回归脚本**、**端到端工具**与**渲染校验**。

## 回归五阶段

```powershell
pwsh -File scripts/regress.ps1
```

| 阶段 | 测什么 |
|---|---|
| 局域网 | 发现、握手、文字、语音流逐字节校验、图片分片与拼装、展示参数、定时、名单、呼叫拼装、分享链接解析、发送队列、设置锁 |
| 中继 | 教室注册、账号、绑定与授权、文字与语音、图片、多班喊话、集体喊话、分享链接兑现、限速 |
| 托盘 | 关窗口是否缩到托盘、进程是否继续接收喊话 |
| 单实例 | 第二个实例是否只提示、不抢占端口 |
| 前端 | 控制台页面的转义与动作接线（每个 `data-action` 都有处理函数、没有冗余分支） |

中继阶段会自己起一台临时服务器（全新的状态目录 + 环境变量），测完自动清理，
不会碰你部署中的实例。

## 端到端工具

```powershell
# 局域网链路
dotnet run --project tools/ClassShout.EndToEnd

# 中继链路（需要先自行启动服务器）
dotnet run --project src/ClassShout.RelayServer -- --urls "http://127.0.0.1:8090"
dotnet run --project tools/ClassShout.EndToEnd -- --relay http://127.0.0.1:8090
```

**跑的都是真实实现**（真的 TCP 连接、真的分帧、真的服务器），不是 mock ——
这个项目里出错的地方几乎都在"两端之间的约定"上，把中间换成假的东西就什么都测不到了。

## 渲染校验

```powershell
dotnet run --project tools/ClassShout.DesignPreview -- artifacts
```

它把真实界面渲染成 PNG，并做像素级判据（颜色数、主色占比、MD3 令牌是否命中），
同时跑几条与渲染无关的断言（字体回退、配色算法、配置读写、图片压缩）。

导出的图要**真的打开看**：像素判据只能说明"画出来了"，排版走没走样、
置灰的项目是不是真的灰、状态徽标有没有出现，只有人看得出来。
需要看折叠状态看不到的部分（例如开关关着时那几张输入框、下拉展开后的置灰项）时，
就单独加一个场景把它展开再渲染一次。

## 两条纪律

1. **断言要能抓住 bug。** 修完一个问题之后，把修复临时退回去跑一遍，
   确认断言真的失败 —— 否则那条断言只是在空跑。
   例如"教室端到插件必须认 chunked"这条：退回之后正文确实变成空串，断言才会红。
2. **不谎报结果。** 集成测试里出现过"接口返回成功但什么都没发生"的情况，
   所以关键的断言都往后多验一步：授权之后还要查"授权列表里真的有这几个班"。
