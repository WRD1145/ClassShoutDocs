# 教室回复

老师喊完一句，教室里那块屏的下方会出现一排回复按钮 —— 点「知道了」、挑一句快捷回复、
打一句话，或者录一小段语音。回复回到老师那边时，**带着原消息的 ID**。

## 教室那块屏上怎么回

四样东西，出现哪几样由教室端的设置决定：

| 怎么回 | 教室里做什么 | 老师收到什么 |
|---|---|---|
| 知道了 | 点一下，一秒完事 | 教室名 +「知道了」（内容可以拼装，默认就是这两段） |
| 快捷回复 | 挑一句预置的说法 | 那句话本身，例如「收到」「马上」「没问题」 |
| 文字 | 现打一句 | 打的那一句 |
| 语音 | 录一小段，说完点「说完了，发送」（到时长上限会自动发） | 一条可回放的语音 + 时长 |

回复按钮只跟着**屏上正显示的那一条**：老师喊一条，这一排才出现；
没有可回复的喊话时，整块回复区是藏起来的。

## 这四样能不能出现，由教室端决定

在教室端 → 设置 →「回复」里。为什么在教室端而不是教师端：回复是教室里那个人
（学生、课代表、下节课的老师）在做，而"能怎么回"取决于这间教室的实际情况 ——
有的教室没有麦克风（语音回复就该关掉），有的班只需要一个「知道了」。
放在教师端的话，同一套按钮会出现在所有教室里。

| 设置 | 默认 | 说明 |
|---|---|---|
| 允许回复 | 开 | 总开关。关掉之后那块屏上不出现任何回复入口 |
| 显示「知道了」按钮 | 开 | 最常用的一颗：一秒点完，老师就知道教室里看到了 |
| 允许文字回复 | 开 | 教室里现打一句话 |
| 允许语音回复 | 开 | 本机没有麦克风时这一项是灰的（Windows 要录音设备，Linux 要 `alsa-utils` 的 `arecord`） |
| 语音时长上限 | 15 秒 | 3–60 秒可调；到时自动发出去，省得教室里说完忘了点停 |
| 快捷回复 | 收到 / 马上 / 没问题 | **最多 6 个**：再多那块屏就摆不下，也点不准 |

这些设置存在本机的 `classroom-reply.json` 里，不含凭据（见[配置文件一览](/reference/config-files.html)）。

## 回复带着原消息的 ID

每条喊话都有一个 ID，而那个 ID **就是它的发送时刻**（`yyyyMMddHHmmssfff`，例如 `20261020233225123`）。
回复原样把它带回去，老师那边才说得清"这条『知道了』是针对哪一句话的" ——
教师端列表里写的就是「回的是 23:32:25 那条」。

回复自己也有这样一个 ID（同样是一次发送时刻），所以教室端回完写「已回复（14:05:03）：收到」，
而「14:05:03」是**这条回复**发出的时刻，不是原喊话的。

用时间戳当 ID 而不是随机串，是为了让两件事免费成立：**日志里一眼读出发送时刻**，
以及**同一条消息在局域网与中继两条路上身份一致**（教师端生成一次，服务器与教室端原样带着）。

## 老师这边：教室回复列表与系统通知

教师端的「教室回复」是一张卡：最新的在最前，最多留 50 条，导航图标上带未读数角标，
进来就算已读。语音回复可以点一下回放。

收到回复时还会弹一条**系统通知** —— 老师这时多半在做别的事，不会一直盯着这一页：

| 平台 | 通知怎么弹 |
|---|---|
| Android | 通知渠道「教室回复」；Android 13 起还要 `POST_NOTIFICATIONS` 权限，第一次会被问一下 |
| Windows | 托盘气泡（Win10 之后会进右下角的通知中心） |
| Linux | `notify-send` |

同一间教室同时挂着局域网直连与中继是常态，所以同一条回复可能从两条路各来一次 ——
按回复自己的 ID 去重，重复的那条直接吞掉：同一条回复弹两次通知，
会让人以为教室里回了两次。

## 网页控制台上的教室回复

用浏览器打开服务器地址、登录之后，老师视图里有「教室回复」面板：能看列表、能回放语音。
面板上的「**开启桌面通知**」让浏览器也弹通知 —— 浏览器只在 **HTTPS** 下允许它，
用 `http://` 打开时这个按钮点不动。

网页端只看不回：回复是教室里那个人做的，网页上没有"替教室回一句"的入口。
