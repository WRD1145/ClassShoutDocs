# 账号与权限：教师 / 班主任 / 管理员

服务器上的账号有三层：**教师 &lt; 班主任 &lt; 管理员**。
差别只在一件事上 —— **谁来决定"哪个班归谁用"**。

| 角色 | 能做什么 |
|---|---|
| 教师 | 给自己被授权的班级喊话；管理**自己的**名单与呼叫模板 |
| 班主任 | 教师的全部，外加**自己当班主任的那几个班**：给别的老师授权 / 收回，上传这个班统一使用的名单（并可设为强制） |
| 管理员 | 全部班级；建号、改角色、重置口令、删教室、分享链接 |

班主任**管不到别人的班**：一位老师可以同时是二班的班主任、又只是三班的任课老师 ——
所以"班主任"这件事记在**每个班的授权**上，而不是只记在账号上。
账号上那个角色决定的是"这个人有没有资格当班主任"。

## 怎么指定一位班主任

管理员在控制台的「班级授权」里授权时勾上「**设为该班的班主任**」：

- 一个班可以有好几位班主任（年级组共同管理是常见做法）；
- 勾上之后这个账号的角色会自动升为班主任 —— 不必分两步（先改角色、再勾班主任），
  少一步就少一种"勾了却什么也管不了"的困惑；
- 反过来把角色降回教师**不会**自动删掉他的班主任授权：那属于"管哪几个班"，
  是另一处的东西，隐式连带删除会让人在别处发现"授权怎么没了"而找不到原因。

## 班主任的「我的班级」

班主任登录网页版之后，老师视图里会多出一块「**我的班级**」：

- 只列出**自己当班主任**的那几个班（一个都没有时整块不显示）；
- 每间班能看到：在不在线、现在授权给了哪些老师、有没有统一名单、是否强制；
- 可以**给这个班授权一位老师**、也可以**收回**（只能收回普通任课老师 ——
  班主任的任免仍然只在管理员手里，否则一位班主任可以给自己拉一个"班主任同伴"，
  两个人的权限互相兜底）；
- 可以上传这个班的**统一名单**，并决定要不要设为强制。

## 名单归谁

名单**按班隔离**：一位老师教三个班，三个班的名单是三分不同的数据。
在此之上，班主任可以给某个班上传一份**全班统一使用**的名单：

| 情况 | 这个班实际用哪份名单 |
|---|---|
| 班主任传了名单，并设为**强制** | 一律用班主任那份；任课老师连上传入口都没有 |
| 班主任传了名单，没有强制 | 任课老师自己传了就用自己那份；没传就用班主任那份 |
| 班主任没传 | 任课老师用自己的 |
| 都没有 | 空 —— 界面上会直接说"这个班还没有名单" |

为什么要有个"强制"：一个班到底按哪份名单叫人，必须**只有一个答案**。
两位老师各录一份时，同一个班里可能一位老师叫得出人、另一位叫不出来，
或者叫出来的名单对不上（转学生补了没有、谁已经调班了）。

> 被强制的班里，任课老师自己的那份名单**不会被删除**，只是暂时不生效；
> 班主任一取消强制，它立刻又生效了。

## 客户端拿到的"我能喊哪几个班"

教师端登录之后，会带着自己的**账号 Id** 问服务器一次：

```
GET /api/teacher/classrooms
X-Auth-Token: <登录令牌>
```

服务器回一份 JSON：绑定的班级、**在线状态**、我在这个班的角色、以及这个班该用哪份名单。
客户端把它和局域网里发现到的教室合成同一份「可发送班级」列表 ——
于是"我能发给谁"这件事在界面上只有一个答案，不必再分成"局域网那台"和"服务器上的那几间"两处去猜。

> 账号 Id 是客户端**自己报上来的**：服务器会拿它和令牌里的账号对一遍，
> 对不上直接拒绝。它不能当授权依据（授权永远只看令牌），
> 但带上它有两个实在的好处 —— 抓包时一眼看得出这条请求是谁发的，
> 以及令牌过期那种"看起来还登着"的状态会立刻以 403 暴露出来。
