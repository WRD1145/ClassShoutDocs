# 排错

按现象找。

## 教师端搜不到教室端

1. 两台设备是不是同一个网段（有些校园网会隔离客户端）；
2. 教室电脑的防火墙有没有放行 **TCP 45900 / UDP 45901**（首次启动时要勾「专用网络」）；
3. 教室端是不是已经把窗口关了却没驻留托盘 —— 那就等于退出了；
4. 直接用手动连接填 `IP:端口` 试试：能连上说明是实现问题，连不上说明是网络问题。

## 填了服务器地址，测试连接总是失败

- 地址格式：允许 `192.168.1.10:8080`，会自动补 `http://`；只支持 http 与 https 两种协议；
- 服务器是不是真的在监听那个端口（在服务器上 `curl http://127.0.0.1:8080/api/health`）；
- 反向代理有没有把它转出去；
- **Android 上如果填的是 `http://`（不是 https），需要应用里已配置允许明文流量** ——
  发布版已经配好；自己改过 `network_security_config.xml` 的话检查那一步。

## 喊话发出去了，教室端没反应

- 教师端顶栏的链路是什么（「局域网直连」还是「公网中继」）？没链路就是没连上；
- 教室端是不是**静音**了 —— 静音时文字与语音喊话都不播放（只记日志）；
- 教室端日志里有没有这条记录（有记录说明收到了，问题在播放/显示那一段）。

## 喊话在 ClassIsland 里不出现

1. 「提示方式」是不是选了带 ClassIsland 的选项；
2. 插件装了吗？ClassIsland 的「提醒」设置里「ClassShout 喊话」这个提供方是启用的吗？
3. 插件目录下的 `classshout-bridge.log` 有没有内容（**没有这个文件就说明没有异常**）；
4. 教室端日志里有没有"投递到 ClassIsland 失败"（只在头几次和每 20 次记一条）。

> 这条投递走的是本机回环地址。曾经踩过一个坑：机器上设着 `HTTP_PROXY` 时，
> 请求会被代理接一手、重新编码成 chunked，而插件当时只认 Content-Length，
> 于是读成空体判成 400 —— 喊话彻底不出现而两端都没有日志。
> 现在教室端这条投递显式关掉了代理，插件两种传输方式都认。

## 图片发不出去

- 图片是不是太大（单张上限 8 MiB，发送前会自动压缩到最长边 1600）；
- 中继链路上分片是 10 KB 一片，网络很差时会慢，但不该失败；
- 日志里有没有"图片没有收全" —— 那说明中途断了一片。

## 定时通知没发

- **应用当时在运行吗** —— 本地定时只在应用运行时有效；
- 是不是**错过超过三分钟**了：那样只标记、不补发（这是有意的，见[定时通知](/guide/schedule.html)）；
- 待发列表里还有没有这条（发失败的任务会留着，能看到原因）。

## 分享链接点不开

- 链接是不是过期了（默认 7 天）；
- 点了之后教师端没起来：桌面端会自动注册 `classshout://` 协议；
  Android 上如果被浏览器拦住，把链接复制出来粘进「设备」页的「用分享链接绑定」；
- 提示"请先登录"：这是有意的 —— 兑现链接必须先登录，否则谁绑的都查不出来。

## 教室端不出声

1. 系统音量、默认播放设备；
2. 朗读引擎选的是哪个：系统语音需要机器上装了语音（Linux 上要 `spd-say` 或 `espeak-ng`）；
3. 选 Edge 在线语音时教室电脑要能上外网，连不上会自动回落到系统语音（日志里会写）；
4. 用设置里的「试听当前语音」单项验证。

## 教室端重启后老师要重新绑定

教室端的 UUID 与口令是持久的，重启不会变。
如果确实变了，说明有人重新生成了身份（控制台上做的），或者换了 Windows 账户 ——
因为配置是按账户存放的。
